1. **Key objective** – Make the already-built `unpause_action` capability (a) visible and documented end-to-end, and (b) composable with `paused_until`, so an admin can pause until a return time with a chosen shift policy that is actually applied — automatically — at resume, with no overdue-notification blast from the paused window.

2. **Summary of recent work** – PR #323 (open) shipped UTC storage + poll-based auto-resume and pinned "auto-resume never shifts". Investigation (2026-09-28) confirmed: `unpause_action` has **zero** test coverage; passing it with `paused=true` is accepted, logged, then silently dropped because it is never persisted; `services.yaml` does not document the field. Resume+shift atomicity was verified sound (no `await` before mutations in `reschedule_chores_after`, `chore_manager.py` ~7075-7230). **Lifecycle audit (D2 condition, verified 2026-09-28 at `chore_manager.py:6531-6535`)**: current code does *not* clear — (a) re-pause with `paused_until=None` hits neither branch, so a previous value survives and can auto-resume against intent; (b) `paused=false` with a provided until *stores it while unpaused*, priming a future pause cycle. Both are pre-existing defects this initiative fixes (release notes: bug + feature).

Resolution: *explicit param > stored intent > `unpause`*, where "bare" = field **absent**. **Three-layer trap (critical)**: "bare" must stay distinguishable from explicit `'unpause'` at ALL of — (L1) schema default (`services.py:711-714`, remove `default=`), (L2) handler fallback (`services.py:4098` `call.data.get(FIELD, UNPAUSE_ACTION_UNPAUSE)` → must become `call.data.get(FIELD)` → `None` when absent), (L3) manager signature default (`chore_manager.py:6502` `unpause_action: str = "unpause"` → `str | None = None`).      - **D3 – Intent lifecycle** *(ratified 2026-09-28 — "lifecycle must be tight"; normative matrix, all writers must obey)*:

       | Call / transition        | `paused_until`                                   | stored action                                  |\       | ------------------------ | ------------------------------------------------ | ---------------------------------------------- |
       | `paused=true` + value    | store (UTC-normalized)                           | store                                          |
       | `paused=true` + omitted  | **clear (pop)**                                  | **clear (pop)**                                |
       | `paused=false` (any params) | **clear** (a provided until is *never* stored) | **clear** (action param = apply-now instruction, never stored on resume) |
       | form save → `paused=False` | **clear both** regardless of submitted payload | **clear both**                                 |
       | form save `False→True` (fresh pause) | per field (`None` = clear)          | **clear** (form supplies none → omission rule) |
       | form save `True→True` (edit while paused) | rewrite from field                        | **preserve** (edit, not a new pause)           |

       Intent never outlives a pause cycle. The canonical method (`set_user_chores_paused`) and the form guard (Phase 2 step 6) are jointly responsible for the table.

     - **D7 – Shift execution timing** *(ratified 2026-09-28 — "shift at unpause": the shift past *now* occurs at the unpause; logical and easiest to implement)*: with `paused=true` + action, the shift is **stored, not executed** — no mutation happens at pause time; the stored intent executes **at resume, atomically with the unpause** (inside `set_user_chores_paused(paused=False)`, before persist/emit and before the same-tick scan ⇒ no overdue, no notifications), with the shift boundary at the **actual resume instant** (not the until value). **Early manual resume works as users expect**: the stored intent applies exactly as originally set (D2 — every resume path), boundary at the early-resume moment. **Cancel paths before resuming** (both guards exist): (1) re-run pause with fields omitted → clears both (D2/D3); (2) resume with explicit `unpause_action: unpause` → explicit beats stored (D2 precedence), then consumed. Alternatives rejected: shifting at pause has no valid boundary (to-now is meaningless; to-until breaks early resume, requires re-shifting on every until edit, and is undefined for indefinite pauses; once shifted it cannot be undone). Sibling-overdue on shared chores *during* a pause exists today regardless of intent and is addressed by the existing Push-then-Pause composition (#253), not by fusing shift into pause. Note: today the action at pause is inert (guard `if not paused…`, `chore_manager.py` ~6549) — D7 defines the ratified end-state.

The companion surprise (*plain resume applies the stored shift*) stays documentation-only: `services.yaml` description + wiki FAQ spell out the two cancel paths.
